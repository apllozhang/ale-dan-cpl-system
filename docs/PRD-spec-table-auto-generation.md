## 1. 背景与目标

### 功能定位

作为"报价单生成功能"的自然延伸，提供商业报价与技术规格的一体化输出能力。解决销售人员在创建报价单后，还需要手动从参数文件中复制粘贴技术规格到独立文档的痛点。

### 核心目标

| 目标 | 衡量标准 | 说明 |
|------|----------|------|
| **自动化** | 参数表生成耗时 < 3 秒（100 行报价单 + 2000 行参数集） | 点击按钮即可生成，无需手动选集 |
| **标准化** | 导出格式统一，通过验收清单逐项检查 | 提升项目投标和客户呈现的专业度 |
| **提效防错** | 参数表创建时间从 ~30 分钟降至 ~1 分钟 | 辅材和无参数配件自动静默留白，不报错不阻断 |

### 已有能力

| 模块 | 能力 | 位置 |
|------|------|------|
| 参数导入 | Excel 多 sheet 导入，自动检测型号列/说明列/参数列 | `productSpecs.importSet` |

### 当前差距（Gaps）

| # | 问题 | 影响 |
|---|------|------|
| G1 | 无自动匹配 — 用户必须手动选择参数集 | 操作步骤多，新用户不知道用哪个集 |
| G2 | 仅精确匹配 — `AP-1234` ≠ `ap-1234` | 型号大小写不一致导致匹配失败 |
| G3 | 无最优集推荐 — 需用户从平铺列表中挑选 | 参数集多时选择困难 |
| G4 | 不支持跨集匹配 — 一次只能选一个集 | 产品型号分布在多个参数集中时，无法一次导出 |
| G5 | 无参数列排序控制 — collectSpecKeys 按出现顺序排列 | 导出的列顺序不可控 |
| G6 | 未匹配项无"近似推荐" — 辅材静默留白，但真正的型号变体也无法识别 | 用户遗漏有效参数 |
| G7 | 预览只读 — 不能在预览中修正参数 | 修正需跳转到参数管理页 |

## 3. 业务流程 (User Flow)

### 前提条件

管理员已在系统中导入最新的"产品数据"与"参数数据"（两者需具备共用主键，即产品型号）。

### 详细步骤

1. **触发**：用户在报价单详情页点击「生成技术参数表」按钮
2. **自动匹配**：系统遍历所有可用参数集，逐个计算覆盖率，选出覆盖率最高的集
3. **结果展示**：渲染参数表预览，分为匹配成功区（含参数列）、未匹配区（留白）、近似推荐区（可选）
4. **参数集切换**：用户可通过下拉框切换到其他参数集，预览实时刷新
5. **导出**：支持导出为 Excel

## 4. 核心功能与逻辑说明

### 4.1 数据匹配逻辑 (Data Mapping Rules)

#### 主键匹配

严格基于 **产品型号 (Product Model/SKU)** 进行匹配。按优先级依次尝试：

| 优先级 | 匹配策略 | 说明 |
|--------|----------|------|
| 1 | 精确匹配（trim） | `item.productModel.trim() === spec.productModel.trim()` |
| 2 | 大小写不敏感 | `item.productModel.trim().toLowerCase() === spec.productModel.trim().toLowerCase()` |
| 3 | 去空格匹配 | 两边分别 trim 后再 `replace(/\s/g, "")` 再比较 |

只要命中任一策略即算匹配成功，不再继续尝试后续策略。同一型号在多个参数集中都匹配到时，取覆盖率最高的集中的结果。

#### 未匹配项处理

| 场景 | 处理策略 |
|------|----------|
| 辅材/配件/跳线/机柜 | 参数列留白（不报错、不阻断） |
| 型号变体（如 `AP-1234` vs `ap-1234`） | 大小写不敏感匹配兜底，仍失败则进入"近似推荐"区 |
| 真正的未录入产品 | 参数列留白 |

#### 智能参数集推荐

1. 加载所有可用参数集（带 `modelCount > 0` 的）
2. 对每个集计算：`覆盖率 = 匹配成功数 / 报价单总产品数`
3. 按覆盖率降序排列，自动选中覆盖率最高的集
4. 预览顶部显示当前集的覆盖率 + 下拉切换框

### 4.2 跨集匹配（P2 阶段）

当前限制：一次只能匹配一个参数集。

升级方案：支持同时从多个参数集中匹配。处理逻辑：

1. 系统按参数集分别进行匹配
2. 合并所有匹配结果
3. 去重规则：同一 `productModel`（经 trim + toLowerCase 后）只保留第一次匹配的结果，匹配优先级按参数集覆盖率从高到低排序
4. 导出时在参数表底部添加备注行："参数来源：集A (N项)，集B (M项)"

### 4.3 报表字段结构

参数表以原有的报价单格式为基础（基线），并在最右侧扩展参数列：

| 列 | 来源 | 说明 |
|----|------|------|
| # | 序号 | 自动生成 |
| 产品型号 | 报价单明细行 | `productModel` |
| 产品说明 | 报价单明细行 | `productDesc` |
| 数量 | 报价单明细行 | `quantity` |
| 参数1 | 参数数据表 | 动态列，来自 `specs` JSON 的 key |
| 参数2 | 参数数据表 | 同上 |
| ... | 参数数据表 | 同上 |
| 参数N | 参数数据表 | 同上 |

> **注**：参数表只展示技术规格，不包含单价和折后价（商业报价信息由报价单本体承担）。两者是互补的两个文档。

参数列的数量和名称动态确定：取所有匹配成功行的 `specs` 字段的 key 的并集。列顺序遵循参数集导入时的原始列顺序（即 Excel 文件中的列顺序）。

### 4.4 UI 与交互规范

#### 操作入口

在 `QuotationDetail.tsx` 操作区：

| 按钮 | 功能 | 说明 |
|------|------|------|
| [生成技术参数表]（已有） | 打开参数表预览对话框 | 用户确认匹配结果后再导出 |
| [导出参数表 Excel]（新增，P2） | 直接导出 Excel，跳过预览 | 使用最优参数集自动匹配，适合熟练用户 |

#### 预览对话框增强

- **覆盖率指示器**：显示 "X% 匹配（N/M 项）"，用绿色/黄色/红色区分覆盖率高低（>80% 绿色，50-80% 黄色，<50% 红色）
- **参数集切换下拉框**：位于预览顶部，显示各集的覆盖率，切换后预览实时刷新
- **未匹配项数量提醒**：显示 "X 项未匹配"，未匹配行灰色背景，参数列留白
- **近似推荐**（P3 阶段，可选）：对未匹配行，若参数集中存在子串包含关系的型号，在对应行显示 ⚠ 提示 + 推荐型号

#### 内容自适应

- 技术参数通常文本较长，前端表格预览和 Excel 导出时，参数列必须支持自动换行（Word Wrap）
- Excel 导出时参数列设置最大宽度（16），超长文本自动换行；其他列宽度保持现有规格

## 5. 异常处理与边界条件

| 场景 | 处理方式 |
|------|----------|
| 参数文本超长（数千字的招标参数） | Excel：设置最大列宽 16 + 强制换行；单元格不截断 |
| 脏数据（特殊字符、不可见字符） | 后端在匹配/导出前清洗：`productModel.trim()` + 去除不可见字符 ` ​` 等 |
| 报价单无产品明细 | 预览按钮禁用（灰显），提示"请先添加产品明细" |
| 无可用参数集 | 按钮可点击，但预览中提示"暂无参数数据，请先导入参数集" |
| 历史版本报价单 | 实时查询当前参数库匹配（产品型号通常稳定，不随版本变化） |
| 所有产品均未匹配 | 提示"当前报价单共 N 项产品在参数库中均无对应记录"，仍可导出（全量留白） |
| 参数集更新后重查 | 预览对话框提供「刷新匹配」按钮 |
| 同一型号在多个集中匹配到 | 取覆盖率最高集中的结果；跨集匹配时按覆盖率排序取第一个 |
| 匹配耗时超预期 | 预览加载时显示 spinner；AC8 要求 < 3 秒 |

## 6. 权限与安全

| 角色 | 参数表生成 | 参数集管理 |
|------|-----------|-----------|
| Creator / Sales Manager / Admin / SuperAdmin | 可查看报价单 → 生成和导出参数表 | — |
| Viewer | 仅查看报价单，不可导出参数表 | — |
| Admin / SuperAdmin | — | 可导入和覆盖"参数数据"表 |
| 普通销售人员 | 可查看报价单 → 生成和导出参数表 | 不可修改参数集，需修正时由管理员操作 |

参数匹配和导出遵循报价单现有的数据权限：只有具备当前报价单读取权限的用户才能触发。
