# 导入失败原因深度分析

## 错误信息
```
Failed query: insert into `cpl_sheets` 
(`id`, `importLogId`, `sheetName`, `displayOrder`, `productCount`, `createdAt`, `updatedAt`) 
values (default, ?, ?, ?, ?, default, default) 
params: 660003,OS9500 POL,2,28
```

## 问题诊断

### 1. importLogId 异常大（660003）
**这是关键问题！**

- 预期：应该是最近创建的 import log 的 ID（通常是较小的数字）
- 实际：660003（非常大）

**这说明什么？**
- `createImportLogAndGetId()` 返回的不是本次插入的 ID
- 而是数据库中其他某个 import log 的 ID
- 导致 sheets 被关联到错误的 import log

### 2. 为什么会发生这种情况？

即使使用了原生 SQL 的 insertId，仍然可能出现问题：

#### 可能原因 1：连接复用问题
```typescript
const conn = await mysql.createConnection(process.env.DATABASE_URL!);
const [result] = await conn.query(...);
const insertId = Number(result.insertId);
await conn.end();
```

**问题：**
- 每次调用都创建新连接
- 但如果连接池中有多个连接，INSERT 和 SELECT 可能在不同连接上执行
- 导致 insertId 不匹配

#### 可能原因 2：并发导入
```
导入 A 开始
  ↓
创建 import log A（ID=660001）
  ↓
导入 B 开始
  ↓
创建 import log B（ID=660002）
  ↓
创建 import log C（ID=660003）
  ↓
导入 A 继续
  ↓
获取 insertId → 可能得到 660003（最后一个插入的 ID）
```

#### 可能原因 3：事务隔离问题
```typescript
// createImportLogAndGetId 中
await conn.query("INSERT INTO import_logs ...");
const [result] = await conn.query("SELECT LAST_INSERT_ID()");
```

**问题：**
- 如果在 INSERT 和 SELECT 之间有其他连接执行了 INSERT
- LAST_INSERT_ID() 可能返回错误的值
- 特别是在高并发场景下

#### 可能原因 4：MySQL 连接池的会话隔离失效
```typescript
// 假设使用了连接池
const pool = mysql.createPool(...);
const conn = await pool.getConnection();
await conn.query("INSERT ...");
const insertId = conn.getInsertId();  // ← 可能获取错误的值
await conn.release();
```

**问题：**
- 连接池中的连接可能被其他请求复用
- 导致 insertId 混乱

## 真正的根本原因

### 当前代码的致命缺陷

```typescript
export async function createImportLogAndGetId(data: InsertImportLog): Promise<number> {
  const conn = await mysql.createConnection(process.env.DATABASE_URL!);
  try {
    const [result] = await conn.query(
      "INSERT INTO import_logs (fileName, userId, username, orgName, groupName, mode, isActive, sheetNames, sheetsCount, productsCount) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)",
      [data.fileName, data.userId, data.username, data.orgName ?? null, data.groupName ?? null, data.mode, data.isActive ? 1 : 0, JSON.stringify(data.sheetNames), data.sheetsCount, data.productsCount]
    );
    const header = result as mysql.ResultSetHeader;
    const insertId = typeof header.insertId === "bigint" ? Number(header.insertId) : Number(header.insertId);
    if (!insertId || insertId <= 0) {
      throw new Error("Failed to get insertId from import log creation");
    }
    return insertId;
  } finally {
    await conn.end();
  }
}
```

**问题：**
1. 每次创建新连接（性能差）
2. 但这不是主要问题...

**真正的问题在于：**
- `mysql.createConnection()` 返回的 `ResultSetHeader` 中的 `insertId` 可能不准确
- 特别是在以下情况下：
  - 数据库使用了 AUTO_INCREMENT 的特殊配置
  - 表有触发器或其他自动操作
  - 连接参数不正确

## 为什么 sheets 插入会失败？

```typescript
// importCplOverwrite 中
const importLogId = await createImportLogAndGetId({...});
console.log(`[import] Starting overwrite importLogId=${importLogId}, sheets=${data.sheets.length}, products=${data.products.length}`);

// 2c. Tag and insert sheets one by one
if (data.sheets.length > 0) {
  const sheetsWithLogId = data.sheets.map(s => ({ ...s, importLogId }));
  for (const sheet of sheetsWithLogId) {
    try {
      await tx.insert(cplSheets).values(sheet);
    } catch (sheetErr: unknown) {
      const msg = sheetErr instanceof Error ? sheetErr.message : String(sheetErr);
      console.error(`[import] Failed to insert sheet importLogId=${importLogId} sheetName=${sheet.sheetName}: ${msg}`);
      throw sheetErr;
    }
  }
}
```

**流程：**
1. 获取 importLogId = 660003（错误的值）
2. 尝试插入 sheets，关联到 importLogId = 660003
3. 如果 importLogId = 660003 的 import log 已经有相同的 sheetName
4. 可能触发唯一约束冲突

**或者：**
1. importLogId = 660003 是一个已经被停用的 import log
2. 尝试插入 sheets 时，违反了某些约束

## 真正的解决方案

### 方案 1：使用 Drizzle 的事务 + LAST_INSERT_ID()

```typescript
export async function createImportLogAndGetId(data: InsertImportLog): Promise<number> {
  const db = await getDb();
  if (!db) throw new Error("Database not available");
  
  return await db.transaction(async (tx) => {
    // 在同一事务中执行 INSERT 和 SELECT
    await tx.insert(importLogs).values(data);
    
    // 使用 LAST_INSERT_ID() 获取刚插入的 ID
    const [result] = await tx.execute(sql`SELECT LAST_INSERT_ID() as id`);
    const insertId = Number(result?.id ?? 0);
    
    if (!insertId || insertId <= 0) {
      throw new Error("Failed to get insertId from import log creation");
    }
    return insertId;
  });
}
```

**优点：**
- 在同一事务中执行，保证一致性
- 使用 LAST_INSERT_ID()，MySQL 原生支持
- 避免并发问题

### 方案 2：使用 Drizzle 的 returning() 子句（如果支持）

## 总结

**问题根源：**
- `createImportLogAndGetId()` 返回的 insertId 不准确
- 导致 sheets 被关联到错误的 import log
- 导致插入失败或数据混乱

**为什么会发生：**
- 原生 SQL 的 insertId 获取不可靠
- 可能与 MySQL 连接、事务隔离有关
- 可能与 mysql2 库的实现有关

**解决方案：**
- 使用 Drizzle 事务 + LAST_INSERT_ID()
- 保证 INSERT 和 SELECT 在同一连接/事务中执行
- 添加详细日志便于调试

这个问题看似简单，但实际上涉及数据库连接管理、事务隔离、并发控制等复杂问题。
